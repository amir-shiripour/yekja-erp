# مستند فنی معماری چندمستأجری (Multi-Tenancy) و ماژول نمایندگی فروش (ResellerHub)
### راهنمای جامع معماری، استقرار در پروداکشن و بازبینی فنی

این سند به عنوان راهنمای جامع فنی برای توسعه‌دهندگان و مدیر فنی پلتفرم تهیه شده است تا جزییات معماری، نحوه ایزوله‌سازی داده‌ها، تفکیک سابدامین‌ها و کانفیگ‌های سرور را تشریح کند.

---

## ۱. خلاصه معماری (Architecture Overview)

سیستم بر پایه **معماری پایگاه‌داده مشترک با تفکیک منطقی (Single-Database Logical Separation)** و **معماری موازی (Parallel Architecture)** طراحی شده است:

* **کلاینت‌های مستقیم سیستم (Direct Clients):** کلاینت‌ها و مشتریان سیستم اصلی که شناسه آن‌ها `tenant_id = NULL` است. این داده‌ها بدون هیچ‌گونه تغییری در دیتابیس باقی می‌مانند و سیستم کنونی دقیقاً مانند قبل به عنوان CRM اصلی کار می‌کند.
* **مستأجرین جدید (Tenants / Subdomains):** هر CRM جدیدی که توسط نماینده یا مدیر کل فروخته می‌شود، دارای یک سابدامین اختصاصی (مانند `clinic1.vardicrm.ir`) و یک شناسه اختصاصی `tenant_id` است.
* **نمایندگان فروش (Resellers):** حساب‌های کاربری سراسری با نقش `reseller` که دارای سقف سهمیه (`max_tenants`) و ماژول‌های مجاز جهت فروش هستند.

```
                                  ┌────────────────────────┐
                                  │      دامنه اصلی        │
                                  │    vardicrm.ir         │
                                  └───────────┬────────────┘
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    ▼                                                   ▼
       ┌─────────────────────────┐                         ┌─────────────────────────┐
       │   سیستم مستقیم شما       │                         │   پنل نماینده فروش      │
       │   (CRM مرکزی شرکت)      │                         │   /reseller             │
       │   tenant_id = NULL      │                         │   مدیریت سهمیه و ساخت CRM│
       └─────────────────────────┘                         └────────────┬────────────┘
                                                                        │ می‌سازد
                                                                        ▼
                                                   ┌─────────────────────────────────────────┐
                                                   │   مستأجرین و کلینیک‌های فروخته‌شده     │
                                                   │   clinic1.vardicrm.ir                   │
                                                   │   tenant_id = 1 (داده‌های ۱۰۰٪ ایزوله) │
                                                   └─────────────────────────────────────────┘
```

## ۲. لایه تفکیک کوئری‌ها (Eloquent Global Scope)

ایزوله‌سازی داده‌ها در سطح پایین‌ترین لایه پایگاه‌داده با استفاده از تریت `App\Tenancy\Traits\BelongsToTenant` و کلاس `App\Tenancy\Scopes\TenantScope` انجام می‌شود:

1. **در سابدامین یک مستأجر (`clinic1`):**
   * کوئری‌های Eloquent به صورت خودکار با شرط `WHERE tenant_id = current_tenant_id` فیلتر می‌شوند.
   * هنگام درج رکورد جدید (`creating`)، فیلد `tenant_id` به صورت خودکار از مستأجر جاری مقداردهی می‌شود.
2. **در دامنه اصلی پلتفرم (سیستم مستقیم شما):**
   * کوئری‌ها به صورت خودکار با شرط `WHERE tenant_id IS NULL` فیلتر می‌شوند تا هیچ داده‌ای از مستأجرین با کلاینت‌های مستقیم شما تداخل پیدا نکند.
3. **در محیط کنسول و کران‌جاب‌ها (CLI / Cron Jobs):**
   * در صورتی که دستوری از آرتیزان اجرا شود و سابدامینی در ریکوئست نباشد، اسکوپ وارد فاز ایمن شده و مانع اجرای دستورات سیستمی نمی‌شود.
4. **ماکروهای Eloquent جهت گزارش‌گیری و سوپرادمین:**
   * `Model::withoutTenancy()->get()`: دریافت داده‌ها بدون اعمال اسکوپ تننسی.
   * `Model::forTenant($tenantId)->get()`: دریافت داده‌های یک مستأجر خاص.
   * `Model::forDirectSystem()->get()`: دریافت اختصاصی داده‌های سیستم مستقیم.

## ۳. لایه شبکه و وب (HTTP Middlewares)

### ۱. میدلور `App\Http\Middleware\IdentifyTenant`
* مسئول شناسایی هاست ریکوئست و استخراج سابدامین.
* **لیست سیاه سابدامین‌های سیستمی:** از ثبت یا استفاده از کلمات رزرو شده سیستمی مانند `admin`, `api`, `www`, `mail`, `system`, `reseller`, `public` جلوگیری می‌کند.
* **بررسی اعتبار لایسنس:**
  * در صورت مسدود بودن: رندر صفحه خطای ۴۰۳ (`errors.tenant-status`).
  * در صورت انقضای اشتراک: رندر صفحه خطای ۴۰۲ (`errors.tenant-status`).
  * در صورت سابدامین ناموجود: رندر صفحه خطای ۴۰۴ (`errors.tenant-not-found`).
* **امنیت سشن کاربر:** بررسی تطابق سشن کاربر با سابدامین جاری؛ در صورت عدم تطابق، کاربر فوراً لاگ‌اوت و ریجکت می‌شود تا نشت دسترسی رخ ندهد.

### ۲. میدلور `App\Http\Middleware\EnsureTenantHasModule`
* محافظت از روت‌های هر ماژول بر اساس لایسنس فعال مستأجر در جدول `tenant_modules`.
* استفاده در روت‌ها به سادگی با: `middleware('tenant.module:booking')`.

### ۳. فیلترینگ سایدبار (`ModuleMenuService`)
* منوهای سایدبار در زمان حضور در سابدامین مستأجر، به صورت خودکار بر اساس ماژول‌های خریداری‌شده فیلتر می‌شوند.

## ۴. ماژول اختصاصی نمایندگی (`Modules/ResellerHub`)

ماژول نمایندگی به صورت یک پکیج استاندارد در ساختار `nwidart/laravel-modules` پیاده شده است:

* **مدیریت سهمیه (Quota):** نماینده دارای یک سقف عددی `max_tenants` است. هر ساخت CRM یک واحد از سهمیه کسر می‌کند و ساخت بیش از سهمیه مجاز توسط سیستم مسدود می‌شود.
* **سرویس ساخت آنی (`TenantProvisioningService`):**
  * اجرای فرآیند در یک تراکنش دیتابیس (`DB::transaction`) کمتر از ۵۰ میلی‌ثانیه.
  * ساخت رکورد `Tenant` و ساخت همزمان کاربر مدیر کلینیک با نقش `admin`.
  * فعال‌سازی ماژول‌های مجاز و ست کردن انقضای لایسنس.
  * تزریق خودکار تنظیمات وایت‌لیبل نماینده (لوگو، نام برند، کپی‌رایت فوتر، شماره پشتیبانی).
* **وایت‌لیبل ۱۰۰٪:** در پنل مشتریان نماینده، هیچ نام یا نشانی از سامانه مادر نمایش داده نمی‌شود.

## ۵. چک‌لیست استقرار در پروداکشن (Production Deployment Guide)

برای استقرار این کدها روی سرور اصلی، مراحل زیر به سادگی انجام می‌شود:

### ۱. تنظیم دامنه‌های مرکزی در فایل `.env` سرور
```env
# دامنه اصلی پلتفرم شما (جدا شده با کاما در صورت وجود چند دامنه)
CENTRAL_DOMAINS=vardicrm.ir,crm.yourdomain.com

# برای اشتراک کوکی سشن روی تمام سابدامین‌ها
SESSION_DOMAIN=.vardicrm.ir
```

### ۲. تنظیم وب‌سرور Nginx (وایلدکارت سابدامین)
کافی است در کانفیگ Nginx دامنه اصلی، نام سرور را به صورت وایلدکارت تعریف کنید:
```nginx
server {
    listen 443 ssl http2;
    server_name vardicrm.ir *.vardicrm.ir;

    root /path/to/crm-laravel/public;
    index index.php index.html;

    # سایر تنظیمات استاندارد لاراول و SSL...
}
```

### ۳. اجرای مایگریشن‌های پایگاه‌داده
مایگریشن‌ها کاملاً افزایشی (Non-Destructive) بوده و بدون قطعی در سرور اجرا می‌شوند:
```bash
php artisan migrate --force
php artisan module:migrate ResellerHub --force
php artisan module:seed ResellerHub --force
```

### ۴. دستورات برگشت‌پذیری (Rollback Safety)
در صورت نیاز به بازگردانی به نسخه قبل:
```bash
php artisan module:migrate-rollback ResellerHub --force
php artisan migrate:rollback --step=3 --force
```
